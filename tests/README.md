# Tests

## `invoice-balance-sheet` — acceptance test for `ifrs/feature-review.md`

A prose skill has no unit tests. This fixture is the substitute: a small, deliberately
defective feature that a Feature review must correctly diagnose.

```
fixtures/invoice-balance-sheet/
  reports.py                  a runnable balance-sheet generator with four planted defects
  sample_balance_sheet.txt    its real output, generated by running it
expected/
  invoice-balance-sheet.md    the answer key
```

The answer key lives **outside** the fixture directory on purpose. A review agent
pointed at `fixtures/` must not be able to read the answers it is being tested on.

### Running it

Open a session that has not seen `expected/`, and ask it to run an IFRS feature review
of `tests/fixtures/invoice-balance-sheet/`, giving `reports.py`, `sample_balance_sheet.txt`
and a period end of 2026-12-31. Then compare its output against the answer key yourself.

The reviewer must not be the same context that wrote or read the key. A reviewer that
already knows the four defects proves nothing by finding them.

### Passing

All four required findings present, each with the Class and Severity the key states.
A missed finding fails. So does a required finding at the wrong Severity — Severity is
what drives the Verdict, so getting it wrong changes the answer to "is this ready?".

Extras from the key's *Acceptable extras* list are fine. Anything under *Must not
appear* fails regardless of what else was found.

### Regenerating the sample output

```sh
python3 tests/fixtures/invoice-balance-sheet/reports.py > tests/fixtures/invoice-balance-sheet/sample_balance_sheet.txt
```

The defects are in the logic, not the data, so the output changes only if `reports.py`
changes — in which case the answer key's figures need rechecking too.
